# B2/B3 closeout contracts

Frozen before implementation. Schema name stays `execution-receipt-v1`. No new operation ids, scheduler, remote worker API, or nextest migration.

## Receipt

`shell` is a declaration. Toolchain paths, versions, wrapper, linker, target directory, and cache identity are observations. `shell_entered: true` is allowed only after a probe in the environment the operation will run. A static explain result is never relabeled as a verified run.

The probe uses `command -v`, `--version`, and `RUSTC_WRAPPER`. An absent wrapper is `not entered`, not an error. The observed `rustc` path is the process that printed the version. `--print-path` is not part of the contract.

## Run binding

The run record stores `operation_id` and `workspace_id` beside `admission_id`. A receipt is returned only when those match the request. Empty stored ids do not match.

`receipt_binding_matches(stored_operation, stored_workspace, requested_operation, requested_workspace) -> Result<(), String>` lives in `nxr-core`. A mismatch returns an error containing `does not match`.

## Target lock

The effective directory is `--target-dir` on the command, then `CARGO_TARGET_DIR`, then `<workspace>/target`. Host and Linux directories stay distinct because their callers pass different values.

`effective_target_dir` and `admit_target` live in `nxr-core`. The lock is an `fs2` file lock at `<target>/.nxr-target.lock`. A dead recorded owner is recoverable. A missing or unreadable owner is not free. Independent directories proceed. NXR does not govern a raw `cargo` process outside this path.

## Coverage

`operations_plan_batch` coverage:

- `empty` when discovery succeeded and nothing changed
- `unknown` when paths changed but no operation was selected, or inputs are empty on a dirty tree
- `partial` when unknown nodes remain
- `complete` only when at least one operation was selected

`authorized` stays false.

## Diagnostics

`runs_get_diagnostics` reads the existing log. Categories are `compile_error`, `test_assertion`, `missing_toolchain`, `policy_refusal`, `resource_refusal`, and `unknown`. A missing file or line stays absent. No model call and no second store.

## Cache reasons

Reasons come from the same identity the cache uses: `source_changed`, `toolchain_changed`, `wrapper_changed`, `target_changed`, `cache_cold`, `cache_hit`, `context_unverified`. Context compatibility is not byte equality.
